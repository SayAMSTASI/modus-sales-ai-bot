## Важно: какие данные нельзя писать в этот файл

Не вставляйте сюда реальные токены, пароли, API keys, client secrets, строки подключения или приватные ключи. Для них укажите только условное имя `secret_ref` и сотрудника, который сможет выдать значение при подключении.

Пример: `Ответ: secret_ref=telegram_bot_token; выдаёт Иванов И.И.`

В MVP обычные настройки, доступы пользователей, лимиты и метрики будут храниться в PostgreSQL. Секреты — там же, но только в зашифрованном виде. Вне БД останутся два bootstrap-секрета:

- `DATABASE_URL` — чтобы приложение смогло подключиться к БД;
- `MVP_MASTER_KEY` — чтобы приложение смогло расшифровать остальные секреты.

Их нужно передавать контейнеру через Docker secret или защищённые переменные сервера. Предлагаемая схема: AES-256-GCM, отдельный nonce для каждой записи, версия ключа, маскирование в админке и аудит создания/замены/удаления.
