# Bitrix CRM Update

## Назначение

Готовить безопасные обновления CRM по итогам встреч и звонков. Сейчас скилл работает в ручном режиме: формирует таблицу для переноса в Bitrix24. В будущем этот же скилл должен управлять записью через MCP-инструменты после явного подтверждения пользователя.

## Обязательный язык

Всегда отвечать на русском языке.

## Режимы работы

### Ручной режим без MCP

Использовать по умолчанию, если нет доступных CRM-инструментов.

Результат:
- краткая CRM-заметка;
- поля для обновления;
- задачи / next steps;
- список данных, которые нельзя заносить как факт;
- вопросы менеджеру.

### Режим с MCP в будущем

Если доступны MCP-инструменты Bitrix24, действовать осторожно:
1. Получить текущую карточку сделки, если указан deal_id или найдено совпадение.
2. Сравнить текущие данные CRM с новой карточкой сделки.
3. Показать proposed changes.
4. Запросить явное подтверждение пользователя.
5. После подтверждения обновить только разрешённые поля.
6. Логически отделить создание задачи, комментария и обновление полей.

Не выполнять write-действия без подтверждения.

## Ожидаемые MCP-инструменты в будущем

Скилл готов к таким инструментам, если они будут добавлены агенту:
- `bitrix_get_deal`
- `bitrix_search_deal`
- `bitrix_update_deal_fields`
- `bitrix_create_task`
- `bitrix_add_timeline_comment`
- `bitrix_get_current_user`

Если инструментов нет, не упоминать ошибку, а работать в ручном режиме.

## Правила безопасности

Запрещено:
- обновлять CRM на основе гипотез;
- записывать ЛПР, бюджет, сроки или конкурентов как факт без подтверждения;
- записывать внутренние сомнения менеджера в клиентскую карточку без нейтральной формулировки;
- создавать задачи с неконкретными формулировками вроде `связаться потом`;
- выполнять массовые изменения;
- менять стадию сделки без явного указания пользователя.

## Формат значений

Каждое предлагаемое обновление должно иметь:
- поле / раздел CRM;
- значение;
- уверенность;
- источник;
- действие: добавить, заменить, уточнить, не заносить.
