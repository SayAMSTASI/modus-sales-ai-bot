# MEDDPICC Deal Review

## Назначение

Проводить квалификацию сделки Modus по MEDDPICC на основе структурированной выжимки встречи, звонка, карточки сделки или заметок менеджера.

Скилл не должен разбирать сырую длинную транскрипцию с нуля, если уже доступен результат `sales-transcript-review`. Если пользователь вставил только сырую транскрипцию, сначала кратко извлечь факты, затем провести MEDDPICC, но не пытаться детально размечать весь разговор.

## Обязательный язык

Всегда отвечать на русском языке. Английские названия элементов MEDDPICC можно оставлять в скобках после русских терминов.

## Внутренние правила квалификации Modus

Использовать правила из `references/meddpicc-modus.md`.

Ключевой критерий SQL: обязательно должны быть определены:
- боль клиента и соответствие Modus;
- ЛПР / владелец бюджета;
- критерии принятия решения;
- процесс принятия решения.

Желательно должны быть определены:
- метрики проекта;
- договорной / закупочный процесс;
- чемпион;
- конкурентное окружение.

Если обязательные элементы не подтверждены, не называть лид SQL.

## Алгоритм

1. Определить, какие данные есть: выжимка транскрипции, карточка сделки, заметки, предыдущий анализ.
2. Отделить факты от предположений.
3. Заполнить MEDDPICC только подтверждёнными данными.
4. Для каждого элемента указать статус:
   - подтверждено;
   - частично подтверждено;
   - гипотеза;
   - не выявлено.
5. Оценить готовность лида: Prospect / новый лид / лид в работе / MQL / SQL.
6. Дать менеджеру вопросы для следующего контакта.
7. Сформировать блок передачи для обновления карточки сделки.

## Запрещено

- Называть контакт ЛПР без подтверждения бюджета или финального решения.
- Считать контакт чемпионом только потому, что он активно задаёт вопросы.
- Выводить наличие бюджета из факта интереса к цене.
- Считать сроки проекта подтверждёнными, если клиент сказал только «интересно» или «посмотрим».
- Подменять бизнес-боль технической задачей без последствий для бизнеса.
- Присваивать SQL-статус, если не закрыты обязательные критерии.
